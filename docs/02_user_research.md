# User research and observation protocol

**Evidence status: no interviews or observations have been supplied.** All fields below are a study guide, not research findings.

## Planned participants
Interview 5 to 10 participants representing contractors, site engineers, project managers and accounts/payment administrators, including users who lack dedicated documentation teams. Obtain explicit consent before collecting business or personal information.

## Interview record
| Field | Required entry |
|---|---|
| Participant code | Anonymous ID, not a name or account |
| Role and project type | Participant's own description |
| Consent and use limitation | Explicit, dated record kept privately |
| Top three repeated pain points | Specific observed or reported examples |
| Evidence workflow | How photos, measurements, drawings and bills move |
| Time and costs | Observed values or participant estimates clearly labelled |
| Claim rejection or correction | Example and what caused it |
| Software/device constraints | Phone type, connectivity, language, accessibility |
| Willingness to use and pay | Independent decision, not leading assumptions |
| Documents offered for pilot | Permissions, anonymisation and retention |
| Interviewer/date | Private research record reference |

## Workflow observation
With permission, observe one claim from site entry through quantity measurement, bill item matching, prior claim comparison, internal review, submission, client certification and payment status. Capture actual work time and hand-offs, missing records, corrections, bottlenecks and demonstrated workarounds.

## Research outcome
Aggregate the top three problems with evidence, mark unknown or contested assumptions, record actual candidate users and pricing feedback, decide one pilot segment, choose an initial real claim format and define the earliest valuable workflow. Store source material privately and link only a redacted evidence ID in public project records.
